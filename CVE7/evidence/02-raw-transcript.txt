## 7) 2026-11-03 更正：换成**真实挂载的 ext4 文件系统**后，结论变了（重要）
把假 /proc/mounts 换成真挂载（device 名里带 pool 名，绕开 read_mount_data 的 strstr）：

    #: mknod /dev/test b 7 0   (loop0 上是一个真 ext4 镜像)
    /proc/mounts(客户机视角): /dev/test /tmp/mnt/test ext4 rw,relatime 0 0

结果：

| 用例 | 请求 | 结果 |
|---|---|---|
| A 对照（同 fs 内改名） | folder=benign_src&new_folder=benign_dst | `modify_sharedfolder_success()`，目录内改名成功 |
| B 跨 fs 改名 | folder=trav_src&new_folder=../../ESCAPED_DIR | **`modify_sharedfolder_error(alert_msg.Action7)`**，`/tmp/ESCAPED_DIR` 未出现 |
| C 跨 fs 建目录 | folder=../../NEW_OUTSIDE_DIR | `create_sharedfolder_success()`，`/tmp/NEW_OUTSIDE_DIR` 出现 |

原因：`libdisk.so::mod_folder()` 调的是 **rename(2)**（Ghidra CALLEES 里可见 `rename @ 0x127d7`），
真机上共享目录是独立 USB 文件系统，`..` 落到 /tmp（rootfs/tmpfs）时 rename 返回 **EXDEV**，被拒。
早先"跨目录改名成功"是因为假 /proc/mounts 让 /tmp/mnt/test 与 /tmp 属于同一个 superblock —— 那是环境假象。

**修正后的结论**：
- `modify_sharedfolder`：未做 `..` 过滤，但 rename 被文件系统边界挡住 —— 只能在同一块盘内改名，
  穿不出共享目录所在的文件系统。**不作为对外漏洞**（最多算"同盘内可移动目录"）。
- `create_sharedfolder`：`mkdir` 不受 superblock 限制，`../../NEW_OUTSIDE_DIR` 能在共享目录之外
  建出 0777 目录 —— **这条成立**，是本次要报的点。

## 8) create_sharedfolder：静态依据 + 更硬的落点（回应审查）
libdisk.so::add_folder() 反编译（0x21fa8）：

    iVar1 = test_if_exist_share(param_2, param_3);
    sVar2 = strlen(param_2); sVar3 = strlen(param_3);
    snprintf(path, size, "%s/%s", param_2 /* mount */, param_3 /* folder */);
    umask(0);
    mkdir(path, 0x1ff);            /* 0777，且先 umask(0) */
    add_folder_at_var_file(...);

没有任何 ".."、"/"、前缀校验；`mkdir` 不受挂载点限制。

动态落点（同一 token、只改 folder）：

| folder 参数 | 结果 | 落点 |
|---|---|---|
| ../../NEW_OUTSIDE_DIR | create_sharedfolder_success() | /tmp/NEW_OUTSIDE_DIR（drwxrwxrwx） |
| ../../etc/CNVD_ETC_DIR | create_sharedfolder_success() | /etc/CNVD_ETC_DIR（drwxrwxrwx） |
| ../../jffs/CNVD_JFFS_DIR | create_sharedfolder_error(Action5) | 未创建（该路径在仿真里不可用） |

`/etc`（root 755）也能建出来，说明不是"只能落在 1777 的 /tmp"，而是 httpd 进程（root）能写的地方都能建。
